核心发现：官方给了一套完整的部署框架 + 现成策略
1. 关节配置
env-omni31.yaml 定义了 31 个关节（含头部 2 个），但策略只控制 29 个（去掉 head_yaw/pitch）。omni_29dof.xml 的 MJCF 模型也正好是 29 个 actuator（头部关节被注释掉了）。
2. 官方已有的策略（全是 ONNX 格式）
模式	模型文件	用途	obs 维度	action
loco_mode（走路）	omni_7dof_63k_2file.onnx	日常行走，带步态相位	90×10=900	29（实际25，手腕补0）
high_dynamic（高动态）	spinkick/fish 等多个 ONNX	旋踢、鱼跃等	149	29
3. high_dynamic 框架——跳高的正确训练方式
这是最关键的发现。HighDynamicPolicy 的运作方式：
运动数据格式：NPZ 文件，包含 joint_pos(T,29)、joint_vel(T,29)、body_quat_w(T,num_bodies,4)
obs 结构（每帧 149 维）：
ref_joint_pos(29) + ref_joint_vel(29) + anchor_ori(6) + 
history[gravity(3) + ang_vel(3) + joint_pos(29) + joint_vel(29) + action(29)] × 5帧
训练方式：reference tracking（跟踪参考动作），不是 AMP 对抗训练
部署：ONNX → RL SDK 的 FSM 状态机直接加载
4. 关节顺序映射
我们的 retarget 输出（URDF 顺序，即 convert_to_amp.py 的 JOINT_NAMES）：
[0:6]左腿   hip_pitch/roll/yaw, knee_pitch, ankle_pitch/roll
[6:12]右腿  同上
[12:15]腰部  waist_yaw/roll/pitch
[15:22]左臂  shoulder_pitch/roll/yaw, elbow_pitch/yaw, wrist_pitch/roll
[22:29]右臂  同上
官方 MJCF/SDK 顺序（motor order）：
[0:6]左腿   hip_pitch/roll/yaw, knee_pitch, ankle_pitch/roll
[6:12]右腿  同上
[12:15]腰部  waist_yaw/roll/pitch
[15:22]左臂  shoulder_pitch/roll/yaw, elbow_pitch/yaw, wrist_pitch/roll
[22:29]右臂  同上
好消息：关节顺序完全一致！ 不需要额外的索引映射。
